# 发布证书与上架签名——完整操作手册

> 目的：把当前 debug 签名换成**发布签名**，让 `.app` 包能真正通过 AGC 审核上架。
> 耗时：约 20–30 分钟。关键阻塞点：**需要你本人设定 keystore 密码**（我不能代设，否则私钥作废）。

## 当前状态（已自动完成）

- AGC 浏览器已停在「开发者管理 > ID、证书和Profile > 证书」页
- 「新增证书」对话框已打开，证书类型下拉已展开（有"调试证书"/"发布证书"两项）
- 现有证书：仅 1 张（调试证书，即你给的 `auto_debug_...cer.cer`）
- 已打出 debug 签名的 `.app`：`发布\sdmuApplication-v3.2.0-signed.app`（可本地安装，不可上架）

## 你需要做的 3 步

### 第 1 步：DevEco 生成 keystore + CSR（需你设密码）

1. 打开 DevEco Studio → 菜单 `Build > Generate Key and CSR`
2. 选择 `New`，填写：
   - **Key store file**：存到 `D:\projects\sdmuApplication\发布\签名\release.p12`
   - **Store password / Key password**：⚠️ 你自己设一个并**牢记**（建议记到密码管理器）
   - **Key alias**：`releaseKey`
   - **Validity**：25 年
   - **Certificate**：填写主体信息（ Organization=山东管理学院，Country=CN 等）
3. 下一步 `Generate CSR` → 存到 `D:\projects\sdmuApplication\发布\签名\release.csr`

产出：`release.p12`（私钥库，妥善保管，别提交 Git）+ `release.csr`（请求文件）

### 第 2 步：AGC 申请发布证书 + 发布 Profile（浏览器已就位）

1. 在已打开的「新增证书」对话框：
   - 证书名称：`SDMU_Release`
   - 证书类型：选 **发布证书**
   - CSR：点"选取"上传 `发布\签名\release.csr`
   - 提交 → 在列表下载 `.cer` → 存到 `发布\签名\release.cer`
2. 左侧菜单切到 **Profile** → 新增：
   - 名称：`SDMU_Release_Profile`
   - 类型：**发布**
   - 关联刚才的发布证书
   - 绑定 APP ID：`com.sdmu.sdmuapplication`
   - **权限申请**：勾选 `WRITE_CONTACTS`（受限权限，需填用途说明："用于用户将校园通讯录联系人保存到手机通讯录"）
   - 提交 → 下载 `.p7b` → 存到 `发布\签名\release.p7b`

### 第 3 步：配置签名 + 重打上架包（我来自动做）

把三件套路径告诉我（`release.p12`/`release.cer`/`release.p7b` 及密码、alias），我替换 `build-profile.json5` 的 signingConfigs，然后：
```
hvigorw --mode project -p product=default assembleApp
```
产出可上架的 `.app`，复制到 `发布\`。

## 关键提醒

| 项 | 说明 |
|---|---|
| debug vs release | 当前 debug 证书不能上架；必须 release |
| 密码 | 必须你设，我设的你不知道=私钥作废 |
| WRITE_CONTACTS | 受限权限，Profile 里必须申请，否则真机装不上/功能失效 |
| .p12 保密 | 绝不提交 Git，只在本地 |
| 目标SDK | 当前 26.0.0，符合 AGC 要求（截图提示 2027 年起检测） |

## AGC 路径速记

- 证书：`开发者管理 > ID、证书和Profile > 证书`
- Profile：同菜单 > `Profile`
- 上架版本：`应用管理 > 山东管理学院 > 应用上架 > 准备提交 > 版本/升级`
